# /Manipulating molecules with Emacs/.

=tochemfig= converts molecular structures into LaTeX/chemfig code directly within Emacs.

[[./default-demo.gif]]

* Requirements

- Emacs 29.1+ with dynamic module support
- [[https://github.com/gicrisf/emacs-indigo][emacs-indigo]] (Emacs bindings for the Indigo cheminformatics library), version 0.10.1 or newer (0.11.1 recommended)
- LaTeX with chemfig and TiKZ packages (for rendering output)

The package generates chemfig code natively in Elisp using =emacs-indigo= for molecular structure handling. No Python or external commands required.

Some output uses helper macros inherited from =mol2chemfig= (charges such as =\mcfplus=, aromatic circles =\mcfcringle=, wavy bonds =\mcfwavy=, fancy bonds =\dbl=/\dbr=/\trpl=, ...). Include mol2chemfig's =mcfmacros= preamble (or equivalent definitions) when rendering structures that use them.

* Quickstart

The following is a SMILES representation of caffeine:

#+begin_src
CN1C=NC2=C1C(=O)N(C(=O)N2C)C
#+end_src

Put point on the SMILES and run =M-x tochemfig=, or open the options menu with =M-x tochemfig-dispatch=.  The dispatch menu is the primary interface: it edits every option interactively and generates with =RET=.  In the minibuffer flow, paste the SMILES, press =RET=, and Emacs inserts the chemfig code directly into your buffer.

#+begin_export latex
\chemfig{
            % 1
      -[:42]N% 2
      -[:96]% 3
     =_[:24]N% 4
     -[:312]% 5
    =_[:240]% 6
               (
         -[:168]\phantom{N}% -> 2
               )
     -[:300]% 7
               (
         =[:240]O% 8
               )
           -N% 9
               (
         -[:300]% 14
               )
      -[:60]% 10
               (
               =O% 11
               )
     -[:120]N% 12
               (
         -[:180]% -> 5
               )
      -[:60]% 13
}
#+end_export

Export the LaTeX document as a PDF to see the rendered molecule:

You can also set these as defaults in your config:

#+begin_src emacs-lisp
(setq tochemfig-default-input 'direct)
(setq tochemfig-default-angle -30.0)
(setq tochemfig-default-flip t)
#+end_src

* Installation

** Prerequisites: emacs-indigo

First, install =emacs-indigo=, which provides the molecular structure handling capabilities:

#+begin_src bash
git clone https://github.com/gicrisf/emacs-indigo.git
cd emacs-indigo
./install.sh
#+end_src

The install script automatically downloads and builds all dependencies (zlib, TinyXML, Indigo library) locally, then compiles the Emacs dynamic module.

Note: =emacs-indigo= defines its =indigo-with-*= resource macros only after its
dynamic module has loaded.  tochemfig works around this at byte-compilation time,
but you should still make sure a stale install is up to date: if you installed
=emacs-indigo= via Doom/straight and have not updated it recently, run
=M-x straight-pull-package RET indigo= (or =doom sync -u=) and rebuild tochemfig.

Add to your Emacs config:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/emacs-indigo")
#+end_src

** Installing tochemfig

*** Doom Emacs

#+begin_src emacs-lisp :tangle packages.el
(package! tochemfig
  :recipe (:host github :repo "gicrisf/tochemfig"))
#+end_src

#+begin_src emacs-lisp
;; in ~/.doom.d/config.el
(add-to-list 'load-path "/path/to/emacs-indigo")
(use-package! tochemfig)
#+end_src

*** straight.el

#+begin_src emacs-lisp
(straight-use-package
 '(tochemfig :type git :host github :repo "gicrisf/tochemfig"))
(add-to-list 'load-path "/path/to/emacs-indigo")
#+end_src

*** Manual

Clone this repository and add both paths:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/emacs-indigo")
(add-to-list 'load-path "/path/to/tochemfig")
(require 'tochemfig)
#+end_src

** Nix

For Nix users, =emacs-indigo= provides a flake:

#+begin_src bash
cd emacs-indigo
nix build
#+end_src

The built package will be available in =./result=. Add the result path to your Emacs load-path, or integrate it with your Nix-based Emacs configuration.

* Usage

The transient menu is the primary interface.  The minor mode adds buffer-aware
commands and automatic wrapping on top of it.

1. *Transient menu* with =M-x tochemfig-dispatch= (also =tochemfig-custom=): it
   works from any buffer and enables =tochemfig-mode= if needed.  It edits every
   option live, uses the region or the SMILES at point as input, and prompts
   when there is no molecule there.

   | Key   | Action                                            |
   |-------+---------------------------------------------------|
   | =RET= | Generate and insert                               |
   | =C=   | Copy generated code to the kill ring              |
   | =F=   | Generate from a MOL file (one-off, no option edit) |
   | =A=   | Rotate the next generation only                   |
   | =?=   | Show the =C-c m= key bindings                     |

   Options are buffer-local, and are only localized the first time you edit
   them, so changes to the global defaults still reach untouched buffers.  Use
   =tochemfig-describe-options= to see the effective values,
   =tochemfig-save-options= / =tochemfig-reload-options= to persist the global
   defaults, and =tochemfig-reset-options= (=C-u= for global) to reset.

2. *Context-aware minor mode* with =tochemfig-mode=: enable it in a buffer to
   generate chemfig code from the SMILES string at point or in the region, with
   output wrapped in =\chemfig{...}= automatically in LaTeX and Org buffers
   (including LaTeX source blocks inside Org).  An optional menu-bar entry
   appears while the mode is active.

   Which major modes count as wrapping contexts is controlled by
   =tochemfig-mode-wrap-modes= (default: =tex-mode=, =latex-mode=,
   =LaTeX-mode=, =org-mode=, =markdown-mode=).  Wrapping is decided per
   command, so a single Org buffer can mix wrapped and unwrapped output.  Set
   =tochemfig-mode-auto-wrap= to nil to disable automatic wrapping.

   | Key       | Command                      | Description                          |
   |-----------+------------------------------+--------------------------------------|
   | =C-c m g= | =tochemfig=                  | Generate for region / point / prompt |
   | =C-c m o= | =tochemfig-dispatch=         | Transient options menu               |
   | =C-c m c= | =tochemfig-copy=             | Copy to the kill ring                |
   | =C-c m d= | =tochemfig-describe-options= | Describe effective options           |

   #+begin_src emacs-lisp
   (add-hook 'latex-mode-hook #'tochemfig-mode)
   (add-hook 'org-mode-hook #'tochemfig-mode)
   #+end_src

   To turn it on everywhere it makes sense, use the global mode (it enables
   =tochemfig-mode= only in the wrapping contexts above; opt into every buffer
   with =tochemfig-global-mode-all-buffers=):

   #+begin_src emacs-lisp
   (tochemfig-global-mode 1)
   #+end_src

** Migrating from the one-shot commands

The old =tochemfig-input-*=, =tochemfig-terse=, =tochemfig-rotate=,
=tochemfig-fancy-bonds=, =tochemfig-wrap-chemfig= and similar commands have been
removed.  They duplicated the transient menu with a fixed option and always
prompted for SMILES.  Use the menu instead:

| Old command                                            | Replacement                                      |
|--------------------------------------------------------+--------------------------------------------------|
| =tochemfig-default=, =tochemfig-input-direct=          | =M-x tochemfig= or dispatch (=RET=)              |
| =tochemfig-input-file=                                 | =M-x tochemfig= with input =file=, or dispatch =F= |
| =tochemfig-terse=, =tochemfig-verbose=                 | dispatch =z=                                     |
| =tochemfig-rotate=                                     | dispatch =a= (persistent) or =A= (one-off)       |
| =tochemfig-fancy-bonds=, =tochemfig-vanilla-bonds=     | dispatch =f=                                     |
| =tochemfig-show-carbons=, =tochemfig-show-methyls=     | dispatch =c= / =m=                               |
| =tochemfig-add-hydrogens=, =tochemfig-delete-hydrogens= | dispatch =y=                                    |
| =tochemfig-aromatic-circles=, =tochemfig-atom-numbers= | dispatch =o= / =n=                               |
| =tochemfig-bond-scale=, =tochemfig-bond-normalize=     | dispatch =s= / =t=                               |
| =tochemfig-markers=, =tochemfig-cross-bond=            | dispatch =g= / =k=                               |
| =tochemfig-wrap-chemfig=, =tochemfig-wrap-submol=      | dispatch =w= / =l=                               |
| output-file variants                                   | =tochemfig-copy=, then save the buffer            |

** Customizing defaults

Set your preferred defaults in your config file:

#+begin_src emacs-lisp
;; Input mode: 'direct for SMILES, 'file for MOL files
(setq tochemfig-default-input 'direct)

;; Use relative angles instead of absolute
(setq tochemfig-default-relative-angles t)

;; Enable fancier double/triple bond rendering
(setq tochemfig-default-fancy-bonds t)

;; Wrap output in \chemfig{...}
(setq tochemfig-default-wrap-chemfig t)

;; Rotate all molecules by default
(setq tochemfig-default-angle -30.0)
#+end_src

The transient menu is the authoritative list of options: open
=M-x tochemfig-dispatch= and press =?= for the key bindings.

** Evil / Doom

=tochemfig-mode= is plain Emacs: its =C-c m= bindings already work in Evil's
normal and visual states, and there is no dependency on Evil.  Doom users
usually make the transient menu the primary entry point and map the top-level
commands under their leader, e.g.:

#+begin_src emacs-lisp
(map! :leader
      (:prefix ("C" . "tochemfig")
       :desc "Options menu (RET generate, C copy, F file, A rotate)"
       "o" #'tochemfig-dispatch
       :desc "Generate at point/region" "g" #'tochemfig
       :desc "Copy to kill ring" "c" #'tochemfig-copy
       :desc "Describe options" "d" #'tochemfig-describe-options
       :desc "Save options as global defaults" "s" #'tochemfig-save-options
       :desc "Reload saved options" "r" #'tochemfig-reload-options
       :desc "Reset buffer options" "R" #'tochemfig-reset-options))
#+end_src

=SPC C o= is the primary entry point.  Inside the menu use =RET= to generate,
=C= to copy, =F= for one-off MOL input, =A= to rotate once and =?= for the
bindings.  The =g=, =c= and =d= leader keys are shortcuts for the same top-level
commands; =s=, =r= and =R= manage the option defaults.  File input and one-off
rotation intentionally have no separate leader bindings: they live in the menu.
The old =C-c m f/t/w/r= shortcuts are gone.

Generating from a visual selection replaces the selection and leaves visual
state.  The =*tochemfig options*= buffer is read-only and uses Emacs state under
Evil, so =q= quits it.  Doom disables the menu bar, so use =SPC C o= /
=C-c m o= / which-key rather than the menu.

* Testing

The chemfig generator is a native port of the reference =mol2chemfig=
implementation. Three layers of tests guard against regressions:

1. *Parity*: ~330 ERT tests compare output against golden files produced by
   =mol2chemfigPy3= for a corpus of molecules and option combinations, plus a
   syntax validator that checks the generated chemfig is well formed.

2. *Structural correctness*: =test/tochemfig-graph-test.el= parses the
   generated chemfig back into a molecular graph and compares it, via
   canonical SMILES, with the graph read directly from Indigo.  This proves the
   output encodes the same molecule *independently of the reference*, and it
   covers the SMILES/layout path that byte parity cannot.  An option matrix
   then re-runs every non-destructive option profile (angles, flips, labels,
   bond scaling, wrapping, markers, fancy bonds, ...) and asserts the molecule
   is unchanged; a randomized generator adds a fuzz smoke test.

3. *Perception agreement*: =tools/check-perception.py= recomputes canonical
   SMILES for every corpus MOL with both =emacs-indigo= and the reference
   =epam.indigo=, and =tools/gen-goldens.py= refuses to regenerate goldens if
   the two builds disagree.

The corpus MOL files carry explicit 2D coordinates, so parity is independent of
the Indigo *layout* implementation: both sides read the same coordinates.
=indigo-unfold-hydrogens= (used by =hydrogens add=) is the exception, because
Indigo itself places the added hydrogens; combinations that depend on that
placement are kept out of the profiled subset.  Golden regeneration also runs
=normalize_header=, which replaces the timestamped program line so output is
byte-reproducible.

The project provides a Nix flake with the required Python reference toolchain:

#+begin_src bash
nix develop          # development shell (Emacs, eldev, reference Python)
eldev test           # run the test suite
tools/gen-goldens.sh # regenerate the corpus and golden files
#+end_src
