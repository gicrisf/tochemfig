# /Drawing chemical structures with Emacs/.

=chem-mode= draws chemical structures from SMILES or MOL files as
LaTeX/chemfig or standalone SVG, without leaving Emacs.

Use it to produce publication-ready structures for LaTeX/Org, or insert SVG
images directly.

[[./default-demo.gif]]

* Requirements

- Emacs 29.1+ with dynamic module support
- [[https://github.com/gicrisf/emacs-indigo][emacs-indigo]] (Emacs bindings for the Indigo cheminformatics library), version 0.13.0 or newer
- LaTeX with chemfig and TiKZ packages (chemfig output only)

The package generates chemfig or SVG natively in Elisp using =emacs-indigo= for
molecular structure handling. No Python or external commands required.  SVG
output needs no LaTeX toolchain.

Some output uses helper macros inherited from =mol2chemfig= (charges such as =\mcfplus=, aromatic circles =\mcfcringle=, wavy bonds =\mcfwavy=, fancy bonds =\dbl=/\dbr=/\trpl=, ...). Include mol2chemfig's =mcfmacros= preamble (or equivalent definitions) when rendering structures that use them.

* Quickstart

The following is a SMILES representation of caffeine:

#+begin_src
CN1C=NC2=C1C(=O)N(C(=O)N2C)C
#+end_src

Put point on the SMILES and run =M-x chem-export=, or open the options menu with =M-x chem-dispatch=.  The dispatch menu is the primary interface: it edits every option interactively and generates with =RET=.  In the minibuffer flow, paste the SMILES, press =RET=, and Emacs inserts the chemfig code directly into your buffer.

#+begin_export latex
\chemfig{
            % 1
      -[:42]N% 2
      -[:96]% 3
     =_[:24]N% 4
     -[:312]% 5
    =_[:240]% 6
               (
         -[:168]\phantom{N}% -> 2
               )
     -[:300]% 7
               (
         =[:240]O% 8
               )
           -N% 9
               (
         -[:300]% 14
               )
      -[:60]% 10
               (
               =O% 11
               )
     -[:120]N% 12
               (
         -[:180]% -> 5
               )
      -[:60]% 13
}
#+end_export

For standalone SVG output, select the =svg= exporter in the transient menu
with =E= (or set =chem-default-exporter= to =svg=), then use =M-x
chem-insert-image= (=C-c m i=).  It writes an SVG file and inserts an
Org/Markdown link, with no LaTeX toolchain required.

Export the LaTeX document as a PDF to see the rendered molecule:

You can also set these as defaults in your config:

(setq chem-default-input 'direct)
(setq chem-default-angle -30.0)
(setq chem-default-flip t)
#+end_src

* Installation

** Prerequisites: emacs-indigo

=chem-mode= uses =emacs-indigo= (the =indigo= package) for molecular input.
Package managers install it automatically because it is declared in
=Package-Requires=.

After installing =chem-mode=, build the native module once with
=M-x indigo-install RET=, then verify it with =M-x indigo-doctor=.  If you
update emacs-indigo later, rerun =indigo-install= and restart Emacs.

Straight, Doom, and =package.el= handle the load path.  Manual installs must
add the emacs-indigo directory to =load-path= (see [[*Manual][Manual]]).

** Installing chem-mode

*** Doom Emacs

#+begin_src emacs-lisp :tangle packages.el
(package! chem-mode
  :recipe (:host github :repo "gicrisf/tochemfig"))
#+end_src

#+begin_src emacs-lisp
;; in ~/.doom.d/config.el
(use-package! chem-mode)
#+end_src

*** straight.el

#+begin_src emacs-lisp
(straight-use-package
 '(chem-mode :type git :host github :repo "gicrisf/tochemfig"))
#+end_src

*** Manual

Clone this repository and add both paths:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/emacs-indigo")
(add-to-list 'load-path "/path/to/tochemfig")
(require 'chem-mode)
#+end_src

** Nix

For Nix users, =emacs-indigo= provides a flake:

#+begin_src bash
cd emacs-indigo
nix build
#+end_src

The built package will be available in =./result=. Add the result path to your Emacs load-path, or integrate it with your Nix-based Emacs configuration.

** Local development with Doom

For development, point Doom at the local checkouts and disable byte/native
compilation so source edits are loaded on the next restart:

#+begin_src emacs-lisp
(package! chem-mode
  :recipe (:local-repo "~/Projects/tochemfig"
           :branch "svg"
           :build (:not compile native-compile)))

(package! indigo
  :recipe (:local-repo "~/Projects/tochemfig/emacs-indigo"
           :files ("*.el"
                   ("build/indigo-module.so" . "build/indigo-module.so"))
           :build (:not compile native-compile)))
#+end_src

Run =doom sync -U= once, then restart Emacs.  Existing =.el= files are read
from the local checkouts on every restart.  Adding or removing files, or
changing autoload cookies, still requires another =doom sync=.

* Usage

The transient menu is the primary interface.  The minor mode adds buffer-aware
commands and automatic wrapping on top of it.

1. *Transient menu* with =M-x chem-dispatch= (also =chem-dispatch=): it
   works from any buffer and enables =chem-mode= if needed.  It edits every
   option live, uses the region or the SMILES at point as input, and prompts
   when there is no molecule there.

   | Key   | Action                                             |
   |-------+----------------------------------------------------|
   | =RET= | Generate and insert                                |
   | =C=   | Copy generated code to the kill ring               |
   | =F=   | Generate from a MOL file (one-off, no option edit) |
   | =A=   | Rotate the next generation only                    |
   | =E=   | Select the exporter (chemfig or SVG)               |
   | =M=   | Insert an SVG image link                           |
   | =?=   | Show the =C-c m= key bindings                      |

   Options are buffer-local, and are only localized the first time you edit
   them, so changes to the global defaults still reach untouched buffers.  Use
   =chem-describe-options= to see the effective values,
   =chem-save-options= / =chem-reload-options= to persist the global
   defaults, and =chem-reset-options= (=C-u= for global) to reset.

2. *Context-aware minor mode* with =chem-mode=: enable it in a buffer to
   generate chemfig code from the SMILES string at point or in the region, with
   output wrapped in =\chemfig{...}= automatically in LaTeX and Org buffers
   (including LaTeX source blocks inside Org).  An optional menu-bar entry
   appears while the mode is active.

   Which major modes count as wrapping contexts is controlled by
   =chem-mode-wrap-modes= (default: =tex-mode=, =latex-mode=,
   =LaTeX-mode=, =org-mode=, =markdown-mode=).  Wrapping is decided per
   command, so a single Org buffer can mix wrapped and unwrapped output.  Set
   =chem-mode-auto-wrap= to nil to disable automatic wrapping.

   | Key       | Command                 | Description                          |
   |-----------+-------------------------+--------------------------------------|
   | =C-c m g= | =chem-export=           | Generate for region / point / prompt |
   | =C-c m o= | =chem-dispatch=         | Transient options menu               |
   | =C-c m c= | =chem-copy=             | Copy to the kill ring                |
   | =C-c m i= | =chem-insert-image=     | Insert an SVG image link             |
   | =C-c m d= | =chem-describe-options= | Describe effective options           |

   #+begin_src emacs-lisp
   (add-hook 'latex-mode-hook #'chem-mode)
   (add-hook 'org-mode-hook #'chem-mode)
   #+end_src

   To turn it on everywhere it makes sense, use the global mode (it enables
   =chem-mode= only in the wrapping contexts above; opt into every buffer
   with =chem-global-mode-all-buffers=):

   #+begin_src emacs-lisp
   (chem-global-mode 1)
   #+end_src

** SVG output and images

The =svg= exporter produces standalone, deterministic SVG without a LaTeX
toolchain.  Select it with =E= in the transient menu, or set it as the default:

#+begin_src emacs-lisp
(setq chem-default-exporter 'svg)
(setq chem-exp-svg-default-theme 'dark)
(setq chem-image-directory "~/org/images/chem/")
#+end_src

=M-x chem-insert-image= (=C-c m i=) renders the molecule at point or in the
region, writes a deterministic UTF-8 SVG file to =chem-image-directory=, and
inserts an Org (=[[file:...]]=) or Markdown (=![](...)=) link.  With a prefix
argument it prompts for the molecule instead of using point.

SVG options use the =chem-exp-svg-default-*= prefix: canvas size and padding,
bond spacing and thickness, font, aromatic display, stereochemistry labels,
and the selected theme.  Themes are centralized in =chem-exp-svg-themes=
(=light= and =dark= by default); add or customize an entry there and select it
with =chem-exp-svg-default-theme=.

** Org Babel

Org support is optional; the core library does not require Org.

#+begin_src emacs-lisp
(with-eval-after-load 'org
  (require 'chem-babel))
#+end_src

Write a SMILES in a =chem-smiles= block and request a file result:

#+begin_example
#+begin_src chem-smiles :results file
CCO
#+end_src
#+end_example

Evaluate with =C-c C-c=.  The result is a deterministic file link:

#+begin_example
#+RESULTS:
[[file:.chem-cache/chem-<sha256>.svg]]
#+end_example

The SVG renderer is the default, and =:exports results= is the default, so
HTML export includes the image.  Toggle inline preview with
=org-toggle-inline-images= (=C-c C-x C-v=).

SVG blocks require =:results file=.  Header options can be added directly:

#+begin_example
#+begin_src chem-smiles :results file :svg-theme dark :svg-width 640 :aromatic circle
c1ccccc1
#+end_src
#+end_example

Use =chem-mol= for MOL text.  For chemfig source:

#+begin_example
#+begin_src chem-smiles :renderer chemfig :results value :wrap latex
CCO
#+end_src
#+end_example

Generated images live in =.chem-cache/= next to the Org file by default.
Customize =chem-babel-cache-directory= to change that; add =.chem-cache/= to
your project's ignore file if appropriate.

Useful commands:

- =chem-org-regenerate-buffer= re-executes every chem block in the buffer.
- =chem-org-clean-cache= removes generated SVGs not linked in the current
  buffer.

A complete executable tour is in
[[file:examples/org-playground.org][examples/org-playground.org]].

** Migrating from tochemfig

=chem-mode= makes a clean break: the old =tochemfig= commands and variables
are not aliased.  See [[file:MIGRATION.org][MIGRATION.org]] for the complete mapping and
optional snippets that recreate the old names in your config.

** Customizing defaults

Set your preferred defaults in your config file:

#+begin_src emacs-lisp
;; Input mode: 'direct for SMILES, 'file for MOL files
(setq chem-default-input 'direct)

;; Use relative angles instead of absolute
(setq chem-exp-chemfig-default-relative-angles t)

;; Enable fancier double/triple bond rendering
(setq chem-default-fancy-bonds t)

;; Wrap output in \chemfig{...}
(setq chem-exp-chemfig-default-wrap-chemfig t)

;; Rotate all molecules by default
(setq chem-default-angle -30.0)
#+end_src

The transient menu is the authoritative list of options: open
=M-x chem-dispatch= and press =?= for the key bindings.

** Evil / Doom

=chem-mode= is plain Emacs: its =C-c m= bindings already work in Evil's
normal and visual states, and there is no dependency on Evil.  Doom users
usually make the transient menu the primary entry point and map the top-level
commands under their leader, e.g.:

#+begin_src emacs-lisp
(map! :leader
      (:prefix ("C" . "chem")
       :desc "Options menu (RET generate, C copy, F file, A rotate, M image)"
       "o" #'chem-dispatch
       :desc "Generate at point/region" "g" #'chem-export
       :desc "Copy to kill ring" "c" #'chem-copy
       :desc "Insert SVG image" "i" #'chem-insert-image
       :desc "Describe options" "d" #'chem-describe-options
       :desc "Save options as global defaults" "s" #'chem-save-options
       :desc "Reload saved options" "r" #'chem-reload-options
       :desc "Reset buffer options" "R" #'chem-reset-options))
#+end_src

=SPC C o= is the primary entry point.  Inside the menu use =RET= to generate,
=C= to copy, =F= for one-off MOL input, =A= to rotate once, =E= to select the
exporter, =M= to insert an SVG image, and =?= for the bindings.  The =g=, =c=,
=i= and =d= leader keys are shortcuts for the same top-level commands; =s=,
=r= and =R= manage the option defaults.  File input and one-off rotation
intentionally have no separate leader bindings: they live in the menu.  The old
=C-c m f/t/w/r= shortcuts are gone.

Generating from a visual selection replaces the selection and leaves visual
state.  The =*chem options*= buffer is read-only and uses Emacs state under
Evil, so =q= quits it.  Doom disables the menu bar, so use =SPC C o= /
=C-c m o= / which-key rather than the menu.

* Testing

The chemfig generator is a native port of the reference =mol2chemfig=
implementation, and the SVG exporter shares the same IR. Six layers of tests
guard against regressions:

1. *Parity*: ~330 ERT tests compare output against golden files produced by
   =mol2chemfigPy3= for a corpus of molecules and option combinations, plus a
   syntax validator that checks the generated chemfig is well formed.

2. *Structural correctness*: =test/chem-graph-test.el= parses the
   generated chemfig back into a molecular graph and compares it, via
   canonical SMILES, with the graph read directly from Indigo.  This proves the
   output encodes the same molecule *independently of the reference*, and it
   covers the SMILES/layout path that byte parity cannot.  An option matrix
   then re-runs every non-destructive option profile (angles, flips, labels,
   bond scaling, wrapping, markers, fancy bonds, ...) and asserts the molecule
   is unchanged; a randomized generator adds a fuzz smoke test.

3. *Perception agreement*: =tools/check-perception.py= recomputes canonical
   SMILES for every corpus MOL with both =emacs-indigo= and the reference
   =epam.indigo=, and =tools/gen-goldens.py= refuses to regenerate goldens if
   the two builds disagree.

4. *SVG exporter*: =test/chem-exp-svg-test.el= covers options/themes, bonds,
   rings, stereochemistry, labels, UI integration, and a 1000-molecule corpus
   smoke test (skipped when the studies corpus is absent).

5. *Org Babel*: =test/chem-babel-test.el= covers block execution, deterministic
   caching, header validation, regeneration, cache cleanup, and HTML export.

6. *SmilesDrawer parity*: =test/chem-svg-parity-test.el= compares native SVG
   primitives against generated SmilesDrawer fixtures using shared
   coordinates.  =tools/svg-raster-report.el= adds an advisory Inkscape raster
   and bond-length report.  See [[file:docs/smilesdrawer-parity.md][docs/smilesdrawer-parity.md]].

The full ERT suite currently has 506 tests.

The corpus MOL files carry explicit 2D coordinates, so parity is independent of
the Indigo *layout* implementation: both sides read the same coordinates.
=indigo-unfold-hydrogens= (used by =hydrogens add=) is the exception, because
Indigo itself places the added hydrogens; combinations that depend on that
placement are kept out of the profiled subset.  Golden regeneration also runs
=normalize_header=, which replaces the timestamped program line so output is
byte-reproducible.

The project provides a Nix flake with the required Python reference toolchain:

#+begin_src bash
nix develop          # development shell (Emacs, reference Python, build tools)
eldev test           # run the test suite (eldev must be on PATH)
tools/gen-goldens.sh # regenerate the corpus and golden files
#+end_src
